# Метод: паспорт проекта, правила запуска, цепочка

## Паспорт проекта

Собирается один раз в фазе 0, вставляется в начало каждого промпта и передаётся каждому субагенту.

```
ПАСПОРТ ПРОЕКТА
- Ниша / тема:
- География: (страна; если услуги на месте — регионы/города)
- Язык: русский
- На чём зарабатываю: (заявки/лиды | CPA-партнёрка | реклама | свои услуги/товар)
- Продукт / услуги / категории:
- Кто клиент: (2–3 фразы — кто эти люди, что им нужно)
- Тип сайта: новый / уже растёт / зрелый
- Главная цель: заявки / трафик / продажи
- Ограничения: (бюджет, время, есть ли эксперт в теме, команда — или всё сам)
- Что уже есть: (домен / страницы / семантика — часто ничего)
```

Чем меньше дыр в паспорте — тем меньше модель додумывает, а додумывает она уверенным тоном, будто это факт. Если дан URL сайта — сначала сними карточку сам (WebFetch), потом дозапроси у пользователя только то, что нельзя увидеть снаружи (цели, бюджет, реальные приоритеты).

## 10 правил запуска

1. Заполняй все переменные — мусор на входе даёт мусор на выходе.
2. Один паспорт проекта на всю разведку — не пересказывай бизнес заново в каждой фазе.
3. Иди по фазам по порядку — каждая опирается на предыдущую.
4. Требуй отделять факт от догадки — «разделяй подтверждённое, вероятное и предположение, не выдумывай цифры».
5. Не верь ни одному выводу в одиночку — сверяй с Wordstat / живой выдачей / отзывами.
6. В следующую фазу передавай выжимку (3–5 выводов + гипотезы + что проверить), а не всю простыню.
7. Стратегические решения (ниша, структура) — на сильной модели, полным ответом.
8. Каждый вывод доводи до действия (конкретной страницы/раздела/приоритета).
9. Спорят два вывода — разбирайся почему, а не выбирай понравившийся. «Спрос большой, но денег нет» — самая ценная находка.
10. Не анализируй «просто посмотреть» — перед фазой ответь: зачем сейчас, какое решение поддержит.

## Цепочка фаз

```
0. Паспорт проекта       → контекст для всего
1. Карта ниши            → границы, подниши, с чего стартовать
2. Светофор ниши         → можно ли новичку (доверие + закон)
3. Проверка выдачи       → пустят ли в топ, есть ли шанс   ← фильтр go/no-go
4. Разбор спроса         → что и сколько ищут (Wordstat)
5. Боли и язык аудитории → о чём люди реально спрашивают
6. Деньги-страницы       → где заявки, а где пустой трафик
7. Гео и архитектура     → сетка городов? типы страниц, сущности
8. Сборка стратегии      → отчёт + контент-план + очередь страниц
```

Фазы 0–3 — фильтр «стоит ли вообще». Если тут no-go — сменить нишу/поднишу, не идти дальше. Фазы 4–8 — когда решено, что заходим.

## Чек-лист «до того как поверить выводу»

- [ ] Вывод конкретен про ЭТУ нишу, а не универсальный шаблон.
- [ ] Нет цифр без источника (или помечены как гипотеза).
- [ ] Конкурентам не приписаны непроверенные факты.
- [ ] Виден уровень уверенности (факт / вероятно / гипотеза).
- [ ] Хотя бы один ключевой вывод проверен руками (выдача / Wordstat / отзывы).
- [ ] Понятно, к какой странице/разделу ведёт вывод.
- [ ] «Высокий спрос» не спутан с «принесёт деньги».
- [ ] Помечено, что реальный Яндекс может отличаться от того, что показал веб-поиск.

## Чего НЕ делать

- Не гонять стратегию на слабой модели.
- Не считать красивый вывод доказанным (уверенный тон ≠ достоверность).
- Не строить решение по одному источнику.
- Не пропускать ручную проверку выдачи и данных.
- Не терять контекст между фазами.
- Не оставлять разведку «красивым документом» без списка страниц и приоритетов.
- Не путать трафик с деньгами.

## Шаблон передачи контекста между фазами / субагентам

```
КОНТЕКСТ ДЛЯ СЛЕДУЮЩЕЙ ФАЗЫ
- Что уже сделали: [фаза]
- Подтверждённые выводы (3–5):
- Главные гипотезы (не проверены):
- Приоритетные подниши / кластеры / темы:
- Риски и ограничения:
- Что проверяем сейчас:
- Требование к достоверности: не выдавать гипотезы за факты, не выдумывать цифры,
  помечать уверенность (высокий/средний/низкий), помнить что Яндекс может отличаться.
```
